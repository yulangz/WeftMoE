# BF16 反向激活倒数修正：完整矩阵（2026-09-18）

候选仅修改 `src/cuda/backward/device_kernels.cuh` 中 BF16 A 检查点后的 sigmoid：普通范围用近似倒数加一次显式 FMA 修正，NaN、溢出与可能产生次正规倒数的范围保留原始除法。导数表达式、BF16 舍入位置和所有 K 归约顺序不变。已采用经过验证的候选文件；生产源码与测试快照逐字节一致。

## 具体实现

修改位于 [backward/device_kernels.cuh](../src/cuda/backward/device_kernels.cuh) 的 `backward_swiglu_epilogue_warp_row`。该函数从 BF16 A/B 检查点及上游梯度计算 SwiGLU 反向；每个元素先将 BF16 A 的位模式展开为 FP32 `av`，再求 sigmoid。旧表达式为：

```cpp
const auto sigmoid = 1.0F / (1.0F + __expf(-av));
```

新实现保留指数及分母的计算，只替换常见范围内的倒数求法，代码为：

```cpp
const float denominator = 1.0F + __expf(-av);
float sigmoid;
if (!(denominator < 0x1p126f)) {
  sigmoid = 1.0F / denominator;
} else {
  asm("rcp.approx.ftz.f32 %0, %1;"
      : "=f"(sigmoid) : "f"(denominator));
  sigmoid = __fmaf_rn(
      sigmoid, __fmaf_rn(-denominator, sigmoid, 1.0F), sigmoid);
}
```

### 1. 近似倒数后用残差修正

令分母为 `d`，近似倒数为 `r`。内层 FMA 计算残差 `e = 1 - d*r`，外层 FMA 计算 `r + r*e`，相当于一次 Newton 倒数修正。两处显式 `__fmaf_rn` 固定融合乘加及舍入行为，避免把表达式拆成独立乘法、减法和加法产生不同中间舍入。目的在于减少常见输入的倒数计算开销，同时恢复这组实际输入所需的位级结果。

### 2. 保留特殊范围的原始除法

`0x1p126f` 是 FP32 的 `2^126`。过大的分母可能得到次正规倒数，而所用近似指令带有 `.ftz`；这些输入走原除法。条件写成 `!(denominator < threshold)`，还会把 NaN 和正无穷送入原分支：NaN 的小于比较为 false，取反后为 true。这个阈值分支只取决于当前元素，不取决于 batch、rank、路由或线程调度。

后续 `silu = av * sigmoid`、`silu_derivative = sigmoid * (1 + av * (1 - sigmoid))`、dA/dB 的 BF16 写回以及 dgate 累加均沿用原表达式和执行顺序。本轮没有把前向 FP32 激活改成同样的倒数路径，也没有更换指数近似或放宽结果容差。

### 3. 为什么验证所有 BF16 编码

这里 `av` 来自已经保存的 BF16 检查点，输入集合只有 65,536 种位模式。因此在 16 张 GPU 上穷举该集合，分别比较旧、新表达式得到的 FP32 sigmoid、SiLU 和导数因子位模式，包括无穷和 NaN 编码；结果均为零位差异。它证明的是当前 SM90a / CUDA 12.9 下、这条实际 BF16 输入路径的等价性，不能据此推导任意 FP32 输入或其他架构、编译器下都逐位相同。

减少逐元素除法开销是实现动机；最终收益以完整 Backward 调用衡量。Flash 四个配置约改善 0.8%，Qwen 有改善、持平及轻微回退，后文保留全部结果。不同配置中该激活阶段占整体耗时的比例不同，不能把局部指令变化直接换算成固定的算子加速比。

## 测量结果与验证

数值依据：上述全编码穷举通过；两模型各 160 份前后向金标准张量逐字节一致；两模型 × EP8/EP16 × 8K/64K 共八组各三次全梯度重复，四类梯度哈希与冻结基线一致；两模型的 Graph、跨 stream、偏斜/空专家、资源池扩容和旧反向状态复用检查通过。该等价性证据限当前 SM90a / CUDA 12.9。

两模型的候选四个前向主核均与基线完整 128 位机器码一致；新增基准时间戳/间隔的新基线六个主核也与旧生产版本完全一致。计时包含 tensor 申请与输入克隆，不包含准备 Forward、rank barrier 或计时外间隔；重复检查在正式计时中关闭。每次 10 次预热、60 次计时，第二轮反转案例与实现顺序，合计 1,920 个样本。所有编译、代码审计和 GPU 正确性检查均与正式计时分开，GPU 作业串行。
