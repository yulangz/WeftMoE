# FC1 打包与查表缓存对照（2026-09-17）

本实验延续[同进程交替对照](fc1_interleaved_20260917.md)，分别测量仅 N256 打包、N256 加精确查表并使用 `__ldcg` 读取。两者均使用原始 A/B 向量检查点写回。公共内存池、初始化和参数布局一致，基线计算仍是原 fullreuse。因此这里隔离计算路径，不能直接当作生产完整修改的收益。

查表版本只把两处 `__ldg` 改为 `__ldcg`，表值、FP32 乘法及 BF16 舍入顺序保持不变。独立程序覆盖 65,536 种 BF16 A 编码、16 种 B 与 16 种 gate，共 16,777,216 组；因子、FP32 输出和 BF16 输出位模式均零差异。两个候选各通过 160 份前后向参考逐字节对比。反汇编中每个前向内核的 128 条表读取从 `LDG.E.CONSTANT` 变成 `LDG.E.STRONG.GPU`；编译器也改变了其他调度和控制位（例如跨节点训练内核指令数 60,136→60,168）。它不是只有读取指令原位变化的硬件缓存对照。

为检查路径间缓存残留，改为连续五轮同一路径后切换；前十轮各预热两条路径五次。正式每次 200 轮、每条路径 100 轮，交换起始路径再测一次。每一组五轮中第一轮标记为切换轮，后四轮单独统计。相邻块中相同位置配对，正差值表示基线较慢。所有样本都保留，不把相关轮次当作独立进程实验。

块状版本只改测试程序，全部十个主计算内核的 128 位机器码与对应参考验证二进制一致；原始与诊断基线的关系见前述报告。每个候选另在 EP8/EP16 64K 各执行 20 次完整输出重复检查，并核对逐 rank 路径标记、WGMMA 计数及输入/权重/输出哈希。正式计时禁用重复检查，GPU 作业串行，所有编译先于计时结束；两节点设置 SM 1620 MHz。

生产源码尚未采用这些候选；本报告不将两个独立进程内 A/B 的差值等同于三条路径同时对照，也不把缓存竞争假说视为已证实。

N256 单独版本在 EP8 的两轮 GPU 配对节省为 72.70/48.40 μs，在 EP16 为 +7.60/−6.40 μs，接近持平。`__ldcg` 查表版本在 EP8 回退 520.95/532.60 μs，在 EP16 回退 157.30/78.30 μs；切换轮和后续轮次均没有显示改善，因此排除此候选。此结果不能证明 L1 缓存竞争是此前回退的根因。
