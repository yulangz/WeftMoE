# Qwen3.5-35B-A3B compact PF profile

H2048/I512/E256/top8, BF16, DP-layout inputs, TP/ETP1, NVIDIA L20X at
1620 MHz. EP8 means one eight-GPU node; EP16 means two nodes. This profile
targets cached training FWD and separately measured fresh-tape BWD, not DT
decode or full-model training. See M14 in the
[optimization record](../../docs/pf_backward_20261012.md) for validation status,
positive and negative ablations, and the Flash regression guard.

Compiled ID: `23023d511ccf`. Arithmetic remains M128/N256/K64, three stages,
cluster-N2; dW uses chunk 1/1. This is a measured candidate, not a claim of a
globally optimal search result.

The final 16-case confirmation meets the 15% throughput target against the
faster p50 of two Megatron baseline runs: EP8 gains 39.8%–95.0%, EP16 gains
15.2%–37.7%. Flash's paired regression matrix shows no distinguishable
systematic regression (maximum increase about 0.11%). Clock settings target
1620 MHz; sparse clock observations and the full caveat are in the record.

- Local: three pull warps, warp-owned M blocks and vector pull; expert-ordered
  compact contributions with a route-to-row map. Use B2048/D2.
- Network: token-ordered node-deduplicated dispatch with coalesced Get,
  window-ordered training tape, precomputed return spans and pending=4.
  BWD Return completion counters are striped by sender; the receiver sums
  them against the exact cumulative node row count in the existing plan.
  Use B1024, channel depth floor=2, credit windows=4. BWD Reduce uses the full
  CTA after dW/return join; network dR is a private per-call workspace slice.
- Credit and all strategy choices are in the generated header and compiled
  ID. `window_tokens` remains a prepare-time choice. Network contribution
  capacity covers the invocation; D does not control wire credits.
- No model-name or hidden-size checks select these strategies in CUDA. Flash
  retains its original profile/default strategy settings.

## Build

Use the repository's CUDA/CUTLASS/NCCL environment:

```bash
export NVCCFLAGS="-lineinfo -DWEFTMOE_FORWARD_USE_GENERATED_TUNING=1 -I${PWD}/configs/pf_qwen35_compact_20261013"
python build_native.py lib --output build/qwen35_compact/libweftmoe.so --jobs 4
python tools/build_tensor_runtime.py --library build/qwen35_compact/libweftmoe.so
```

Set `WEFTMOE_TENSOR_EXTENSION` to the printed extension path. Remove
`WEFTMOE_PF_MIN_RING_DEPTH` and `WEFTMOE_PF_CREDIT_WINDOWS` environment
overrides to use the compiled capacities. Existing applications may still
override them explicitly; doing so changes the measured configuration.

`table.json` supplies exact prepared-capacity lookups for the measured 8K/20K
traces: max tokens 10055/25820 on EP8, 10277/25820 on EP16. Set
`WEFTMOE_AUTOTUNE_TABLE` to its absolute path to select B2048/B1024 respectively.
It is an offline result, not first-call JIT. Other prepared capacities require
separate entries and validation; a compiled-ID mismatch is rejected collectively.
The [machine-readable measurements](../../benchmarks/results/qwen35_pf_compact_20261013.json)
retain the workload hashes and sample timings, including their validation status.

`candidate.json` is the complete combined configuration, including compatibility
fields not active in the current kernels. The header is generated by
`tools/autotune_training.py::generated_header`, not maintained separately.
New strategies are ordinary V4 search axes in `tools/static_forward_tuning.py`.
Do not leave fixed ring environment overrides in an autotune search that varies
`network_min_depth` or `network_credit_windows`.

To reproduce one EP16 cell with per-call work included:

```bash
python benchmarks/run_pf_network.py --artifact build/qwen35_compact --nodes 2 \
  --label qwen35_cached_forward_balanced --master-port 26300 \
  --benchmark tools/benchmark_training.py -- \
  --backend pf --hidden 2048 --intermediate 512 --experts 256 --top-k 8 \
  --ring-tokens 1024 --ring-depth 2 --route-distribution balanced \
  --tokens 8192 20480 --forward-only --prime-trace --warmups 4 --samples 16
```

Use a fresh label/port for each run. Substitute `--backward-only` to time a
fresh-tape BWD, `random` for hotspot routing, or `--nodes 1`/`--ring-tokens 2048`
for EP8. The matching baseline uses `--backend megatron`. PF fixed pools and
both allocators are warmed; per-call cache/workspace allocation remains timed.
Both backends use the comparable cached-activation boundary. These are not
full-model RL step timings.
